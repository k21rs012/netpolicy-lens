# Snapshot管理の検証（2026-10-04）

## 実装

- 共通Snapshot選択をMatrix、Path、機器詳細、Policy、Parser Debug / JSON Exportへ適用。ブラウザ保存による再読込後の選択維持。
- 履歴の名前・ID検索、名前変更、確認ダイアログ付き削除。
- 名前変更でID・作成日時・モデルを維持。削除はSQLiteトランザクションで関連configと一括処理。
- 選択中の削除後は最新の残存Snapshotへ切り替え、全件削除後は空表示。
- 削除後はMatrixキャッシュを破棄。存在しない明示IDへの読み取りは404。

## 検証結果

- Backend: 380件成功。改名の永続化、空白・長さ・型の検証、削除後404、キャッシュ破棄、最終削除、DBエラー時のロールバックを含む。
- 画面E2E: 34件成功。追加した390px / 1440pxの長い名前・削除確認・削除失敗の検証を含む。追加2件は最終CSSとデスクトップのダーク表示でも再実行して成功。
- 実API統合: 4件成功。一時DBで構成切替によるALLOW / DENYの変化、選択の再読込維持、選択した構成のExport、改名、削除のキャンセル・実行・全件削除を確認。
- Frontend本番ビルド成功。モバイルとダークモードの削除ダイアログを画像でも確認。

## 適用範囲

検証は専用の一時DBとローカルのテストサーバーで行った。実データの削除や稼働中環境へのデプロイは行っていない。削除取り消し・自動世代管理・バックアップは今回の対象外。
