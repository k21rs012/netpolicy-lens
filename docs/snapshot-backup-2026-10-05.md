# Snapshotバックアップ・復元（2026-10-05）

Snapshot単位で保存config・解析モデル・メタ情報をJSONへ書き出す。復元プレビューで形式、バージョン、SHA-256、機器数、モデルの型・フィールド・参照を検証し、復元時も同じ検証を行う。最大50 MiB・500 config。既存Snapshotは上書きせず、新IDで追加して解析対象に選択する。

元のParserバージョンとモデルを保持し、configを再解析しない。復元元のID・名前・作成日時を保存する。書き出し・復元とも既存の資格情報マスクを適用する。マスクした資格情報の元の値は復元できない。

## 検証

- Backend 414件成功。往復復元と通信判定一致、削除後復元、改変・不正バージョン・不正モデル拒否、サイズ制限、再マスク、DB障害時のロールバック、既存DB移行を含む。
- 既存画面E2E36件と、追加した復元失敗・再操作・プレビュー破棄テスト1件が成功。
- 実API統合6件成功。専用一時DBで書き出し・削除・内容確認・復元・再読込を検証。
- Frontendビルド成功。モバイルの復元プレビューとダーク表示を画像確認。

## DBと反映状況

復元元情報を保持するため、snapshotsにrestored_from列を追加する移行を実装した。最初のBackendテスト起動時、従来のapp.main初期化が開発用backend/data/netpolicy.dbにもこの列を追加した。保存構成の変更・削除・復元は行っていない。その後、tests/conftest.pyでアプリの初期化段階から専用一時DBへ隔離し、全Backendテストを再実行して成功した。

稼働中サーバーの再起動やデプロイは行っていない。自動世代管理、全履歴の一括復元、暗号化は対象外。
